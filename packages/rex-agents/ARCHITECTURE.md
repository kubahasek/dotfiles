# Architecture — normal Pi and reusable interaction

The parent extension resolves a version-3 per-parent binding and connects to a detached coordinator. Managed children skip recursive parent installation. The model interface is exactly launch/followup/steer/reply/stop/inspect. Mutation IDs remain explicit and stable; inspection has optional agent/question-page selectors but no required mutation identity.

Domain mutations commit authenticated state and idempotency receipts atomically. Queries authenticate and validate fail-stop before returning live cloned data, without transactions/receipts. Heartbeats update a volatile map, not serialized state. Internal poll/answer-inbox/overview remain for control/status; no separate model query tools exist. Obsolete usage/ledger/totals operations are rejected. State schema 4 rejects historical accounting schemas without modifying them.

Inspection includes cumulative per-child token/cost summaries and combines explicit lifecycle/result, bounded pending-question pages/previews, recent progress previews, command counts, launch/delivery uncertainty, public Rex pane presence and ephemeral heartbeat age. Unknown discovery/heartbeat is distinct from missing. No query adopts resources, clears uncertainty or starts processes. Public agent fields are explicit and exclude bearer secrets and profile/instructions.

Launch intent precedes Git/Rex side effects. Duplicate identity never repeats those effects. An uncertain launch stays uncertain, even when inspection finds a matching pane label. No reconciliation/adoption/retry API remains. Followup/steer/reply verify an open recorded owned pane before queueing input; stop remains available even when disconnected/uncertain. Closed panes are never automatically resumed/relaunched.

The Node wrapper spawns one ordinary interactive Pi CLI with inherited environment/HOME/auth/tools/resources, initial model, appended guidance, persistent session and bridge extension. No custom SDK runtime/auth, tool gate, shell interception or immutable-model enforcement remains. Stable canonical root checks remain because Pi normalizes path spellings. Role guidance is not a security boundary.

Explicit shared/worktree selection, dirty-file preservation and pane placement/focus remain unchanged. All shared agents may write and serialize within the coordinator. Parent edits and independent coordinators need external serialization. One parent controller per identity is supported.

Delivery uses stable persisted input markers and attempted/submitted records. Only observed actual user-message persistence releases ACKs. Restart without proof is visible uncertainty with no automatic replay. Basic immutable answer batches retain all ready replies in one user input; no selective member retries, decision IDs or history machinery exist. Stop polling runs before delivery and can abort during uncertainty. Whole-run question/result pause remains. Idle is not an explicit result, nor is stop command acceptance proof of abort settlement. Stale generations cannot mutate later tasks.

Usage scans deduplicate transcript leaf identities within the stable session and persist only complete per-session aggregate snapshots. A child journal revision orders changes; unchanged scans do not journal, and the coordinator ignores stale/repeated revisions without receipts or writes. Unknown prices remain explicit; all-zero rates require known-free configuration. Group overview sums child snapshots only. Followups retain totals, and children publish without a parent connection. Parents use the existing status slot, have no cost journal, never ingest their own transcript, and safely skip UI work headlessly.

`notifications.mjs` owns parent wake-up deduplication and native follow-up delivery. The authenticated read-only notification query derives stable bounded semantic identities from current child questions, settled results, reported failures and uncertainty. Parent polling batches notices; transcript custom-message proofs survive reload, while volatile queued identities prevent repeated native submissions before persistence. Busy work is never aborted or steered; progress/cost changes and non-TUI sessions never wake a model. This is notification glue, not another durable delivery engine.

Rex owns children independently of parent disconnection. Parent-managed cleanup may close identified panes only after accepting results and deciding no followup remains. Retain transcripts/worktrees/branches/state. Legacy isolated runtimes/state remain untouched and unsupported by the new path. No automatic migration/cleanup/deployment/global settings changes are performed.

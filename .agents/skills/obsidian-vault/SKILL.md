# Obsidian Vault

Use `kubahasek/obsidian-vault` as Jakub Hašek's persistent personal knowledge base. Use GitHub connector for all repository access.

## Read

1. Start with `INDEX.md` to orient within vault.
2. Locate and read relevant canonical notes before answering. Use journal and source notes as evidence when relevant.
3. State uncertainty when vault lacks support; do not invent memory or conclusions.

## Write or update

1. Read `VAULT.md` before any change. Treat it as detailed maintenance policy.
2. Prefer updating existing canonical note. Create note only when subject warrants independent, durable page.
3. Preserve `Journal/` and `Readwise/` as source/evidence layers; do not rewrite them into canonical claims without support.
4. Update `INDEX.md` if canonical structure changes.
5. Append meaningful maintenance operations to `LOG.md`.

## Boundaries

Never save transient chat, unsupported inference, or private detail not intended as durable knowledge. Keep edits minimal, attributable, and consistent with repository guidance.

Read `LOG.md` when prior maintenance, provenance, or earlier structural decisions matter. Defer all detailed organization and maintenance rules to vault files.
